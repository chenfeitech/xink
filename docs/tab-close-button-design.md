# 标签关闭按钮视觉优化 — 设计文档

> 状态：**两轮均已实施，第二轮待人工验收**（2026-10-09）
> 第二轮见 [§6](#6-第二轮增强对比度与可见性2026-10-09) —— 第一轮偏向"低调"，
> 用户反馈不够醒目，本轮把目标调整为"常态即可见"。
> 需求：`docs/REQUIREMENTS.md` R2.6
> 范围：`src/ui/editor.rs` 中笔记标签的关闭按钮（渲染那一段）

## 1. 现状与问题

关闭按钮在标签渲染里（`src/ui/editor.rs:654-668`）：

```rust
.child(
    div()
        // 独占点击，避免同时触发标签的选中
        .occlude()
        .child(Button::new(button_id).icon(IconName::Close).on_click(...)),
)
```

**粗大感的成因**：`Button::new(...).icon(...)` 没有指定尺寸与变体，
于是用了组件库的**默认尺寸 + 默认变体**——在紧凑的标签里显得又大又重。

对照同文件工具栏按钮的写法，它们统一是 `.small().ghost()`，风格更轻。
两者不一致，也是"不够精致"的观感来源之一。

## 2. 目标 / 非目标

**目标**

- 视觉尺寸收敛：图标约 **13px**
- 变体统一为 **ghost**：平时无边框无背景，只在交互时出现反馈
- 保持点击可靠性：热区 **≥ 20×20px**
- 与工具栏按钮风格一致

**非目标**

- 不改关闭行为（尤其是 `close_editor_tab` 的"最后一个标签只清空、不移除面板"不变式）
- 不引入新依赖、不新增配置项
- 不做图标动效或大规模重构标签

## 3. 方案

| 维度 | 做法 |
|---|---|
| 图标 | `Icon::new(IconName::X).with_size(Size::Size(px(13.)))`：`X` 比 `Close` 线条更简；显式指定尺寸，不依赖按钮默认值 |
| 变体 | `.small().ghost()`，与工具栏按钮一致 |
| 热区 | 外层 `div().occlude().p_1()`——**用 padding 扩大点击区**，而不是把按钮本身放大，做到"看起来小、点起来大" |
| hover / active | 由 `ghost` 变体内置的交互反馈提供（淡背景 + 图标色增强），不自定义颜色 |
| 间距 | 与标签名保持 `gap_1`，不挤压标题 |

关键点：**视觉尺寸与点击热区解耦**。单纯把按钮调小会降低可点击性，
因此缩的是图标与变体，点击范围靠外层 padding 保住。

## 4. 约束

- 保留 `.occlude()` 独占点击，避免点关闭时同时触发标签选中
- 颜色一律走主题 token，明暗主题都要清晰可辨
- 改动只在标签渲染这一段内

## 5. 验收

1. 按钮明显小于原来的默认尺寸，与工具栏按钮风格一致
2. ~~平时几乎看不到边框/背景，hover 才有轻微反馈~~ —— **该条已作废**：
   常态隐形导致用户找不到按钮，第二轮改为"常态即可见"（见 §6）
3. 点击热区 ≥ 20×20px，点击仍能准确关闭标签
4. 关闭最后一个标签时行为不变（编辑区变空白页，而不是消失）
5. 明暗主题下都清晰可辨

## 6. 第二轮：增强对比度与可见性（2026-10-09）

### 6.1 问题

第一轮选了 `.ghost()`：常态无边框、无背景、图标色偏弱，**必须 hover 才显形**。
实际使用中反馈"找不到、不醒目"——"低调"与"易识别"目标冲突时，第一轮偏向了低调。

### 6.2 目标 / 非目标

**目标**

- 常态即可见：不 hover 也能立刻看到关闭叉（这是本轮的核心）
- hover / 点击有强反馈，并且**语义明确**（关闭 = 危险操作，用 danger 色）
- 明暗主题下对比度都足够

**非目标**

- 不改关闭逻辑（最后一个标签→空白页的规则不变）
- 不改标签的其他部分（标题、未保存圆点）
- 不做动画

### 6.3 方案对比

| 方案 | 常态 | hover | 代价 / 评价 |
|---|---|---|---|
| **A 自定义容器 + hover 变红底**（推荐） | 前景色 14px 叉，明确可见 | `danger` 底 + `danger_foreground` 反色图标 | 最突出、完全可控；代价是失去 `Button` 内置的 tooltip 与键盘焦点环 |
| B `Button` 改 `.outline()` | 细边框 + 前景图标 | 组件内置反馈 | 改动最小、保留组件行为，但"突出"程度中等 |
| C 保持 `ghost`，只加大图标 | 仍然隐形 | 轻微 | **不解决问题** |

**推荐 A**。若实现中发现容器不支持 tooltip，可退回 B。

### 6.4 方案 A 的细则

| 维度 | 做法 |
|---|---|
| 容器 | 固定 20×20 方形、内容居中、圆角 4 —— 视觉尺寸与热区合一，不再靠外层 padding |
| 常态 | 图标 14px，`.text_color(cx.theme().foreground)`（**不用 `muted_foreground`**，那正是对比度不足的原因） |
| hover | `.hover()` 切到 `bg(cx.theme().danger)` + `text_color(cx.theme().danger_foreground)` |
| 点击独占 | 保留 `.occlude()` |
| 指针 | `.cursor(CursorStyle::PointingHand)`：补回裸容器失去的 `Button` 内置反馈 |
| 提示 | **未加 tooltip** —— 见 §6.7 R2：div 的 `tooltip` 要传构造视图的闭包，只有 `Button` 的才收字符串 |

与第一条方案的关键差异：**视觉尺寸与热区合一**（20×20 本身就是热区），
不再"看起来小、点起来大"——因为本轮要求"看起来也要够大"。

### 6.5 约束

- 颜色一律走主题 token（`foreground` / `danger` / `danger_foreground`），**不硬编码**
- 保留 `.occlude()`，点关闭不能同时触发标签选中
- 热区 ≥ 20×20px
- 只改标签渲染这一段，不动关闭逻辑
- 明暗主题都要实测：深色主题下 danger 底不能刺眼，浅色主题下常态图标不能发灰

### 6.6 验收

1. 不 hover 时也能立刻看到关闭叉，对比度明显高于改前
2. hover 时出现红色底 + 反色图标，反馈明确
3. 热区 ≥ 20×20px，点击准确且不触发标签选中
4. 活动标签与非活动标签上都能看清
5. 明暗主题下对比度足够
6. 关闭最后一个标签时行为不变（编辑区变空白页）

### 6.7 风险

| # | 风险 | 处置 |
|---|---|---|
| R1 | 每个标签都有可见按钮，视觉噪音增加 | 常态只给图标色、不给底色；底色只在 hover 出现 |
| R2 | ~~容器不支持 tooltip~~ | **已发生并按预案处置**：`div` 的 `tooltip` 要求 `Fn(&mut Window, &mut App) -> AnyView` 闭包，只有 `Button` 的 `tooltip` 才收 `&'static str`。已省略，靠对比度与指针样式识别（不退回方案 B） |
| R3 | 标签多、宽度紧张时按钮挤压标题 | 固定 20×20，若实测挤压则缩到 18×18（不低于 18，否则热区不足） |
