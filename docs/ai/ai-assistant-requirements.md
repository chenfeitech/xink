## 1. 背景与目标

xink 的 P0（库 / 编辑 / 预览 / 会话恢复）与 P1（双链 / 反链 / 标签 / 搜索 / 大纲 / 命令面板）已交付，
笔记的**组织能力**有了，但**内容生产与整理**仍全靠手工。用户希望：

1. 选中一段文字就能让它「改写 / 扩写 / 翻译」，结果可看、可改、可撤；
2. 整篇笔记能一键生成摘要、标题、标签，能续写；
3. 库级能做「整理」类工作：批量打标签、生成 MOC、找出断链与孤儿笔记；
4. 这些能力**可扩展**：用户自己写一个 skill 就多一个动作。

**设计原则（继承自项目铁律）**

- **本地优先**：AI 是可选能力，未配置时应用行为与现在完全一致，绝不静默联网。
- **磁盘是真值**：AI 不直接改文件，所有修改经 diff 预览与用户确认，改前留快照。
- **领域层可测**：provider 通信、SSE 解析、prompt 组装、diff 计算全在 `core/ai/`，不碰 UI 类型。

## 2. 术语

| 术语 | 含义 |
|---|---|
| Provider | 一次对话的后端：OpenAI 兼容 HTTP 接口，或本地 CLI Agent（codex / claude） |
| 动作（Action） | 一个具名的 AI 操作，如「润色」「生成标签」；有内置动作与 skill 动作两类 |
| Skill | 用户/库作者用 `SKILL.md` 定义的扩展动作（Agent Skills 格式） |
| 上下文 | 发给模型的笔记内容：选中文本 / 整篇 / 多篇 / 检索召回的片段 |
| Diff 预览 | AI 产出与原文的对照面板，用户接受后才落盘 |
| 快照 | 接受修改前把原文另存到应用数据目录，用于人工回退 |

## 3. 目标 / 非目标

**目标（G）**

| # | 目标 |
|---|---|
| G1 | 用自然语言对笔记内容做生成 / 改写 / 加工，结果可预览、可撤销 |
| G2 | 用 AI 做库级整理：标签体系、MOC、断链与孤儿检出 |
| G3 | 动作可扩展：用 `SKILL.md` 定义自己的动作 |
| G4 | 可替换后端：换 base_url / model / key 即用；CLI Agent 作为第二 provider |
| G5 | 全程可控：默认关闭、显式确认、可取消、有错误提示 |

**非目标（NG）**

| # | 非目标 | 理由 |
|---|---|---|
| NG1 | 内置本地大模型推理 | 体积与质量都不划算；本地场景走 Ollama 兼容端点 |
| NG2 | MCP 客户端（P2） | 见 eval §4.4 |
| NG3 | 向量 / embedding 检索（P2） | 见 eval §7.3 |
| NG4 | 多用户 / 团队协作、云端同步 | 本地优先，与定位冲突 |
| NG5 | AI 自动后台改写（无人值守批量改盘） | 与「磁盘是真值 + 显式确认」冲突 |
| NG6 | 图片 / 语音多模态输入 | 当前编辑与预览链路不含多模态 |

## 4. 功能需求

### A1 Provider 与连接

| # | 需求 | 验收标准 |
|---|---|---|
| A1.1 | 支持 OpenAI 兼容接口：可配置 `base_url` / `model` / `api_key` | 填入 DeepSeek 或 Ollama 的端点后可正常对话 |
| A1.2 | 凭据存放遵循设置项 Q1 的决定（默认 Keychain） | `config.json` 里不出现明文 key |
| A1.3 | 未配置 provider 时，AI 命令显示「未配置」并可一键跳设置 | 不发起任何网络请求，无报错弹窗 |
| A1.4 | 提供「连接测试」按钮，展示耗时与错误信息 | 错 key / 错端点 / 超时分别给出可读提示 |
| A1.5 | 请求可取消（Esc 或面板按钮） | 取消后不再有增量回调，UI 回到空闲态 |
| A1.6 | 超时可配（默认 60s）；流式静默超过该时长判失败 | 不会一直转圈 |
| A1.7 | 支持 CLI Agent provider（P1，见 eval §4.2） | 同一动作在两个 provider 下结果形态一致 |

### A2 单篇：选中文本动作

| # | 需求 | 验收标准 |
|---|---|---|
| A2.1 | 有选中文本时，可用命令/右键触发 AI 动作 | 无选中时命令不可用并说明原因 |
| A2.2 | 内置动作（Q4）：润色、扩写、精简、翻译、改标题、生成摘要、生成标签、续写 | 8 个动作逐一可用 |
| A2.3 | 结果在面板中**增量显示**（流式） | 长回答能看到文字逐步出现 |
| A2.4 | 以 diff 形式展示「原文 → 建议」，可整体接受 / 丢弃 | 未接受时磁盘与编辑器内容不变 |
| A2.5 | 可选「插入到光标处」而非替换 | 插入位置正确，不破坏现有 Markdown 结构 |
| A2.6 | 输出语言默认跟随正文（可配，Q5） | 中文笔记得到中文结果 |

### A3 单篇：整篇动作

| # | 需求 | 验收标准 |
|---|---|---|
| A3.1 | 对整篇执行动作（无选中时默认整篇） | 摘要 / 标题 / 标签落在 frontmatter 或文首，位置可配 |
| A3.2 | 超长笔记按 `max_context_chars` 截断并在 prompt 中声明节选 | 面板上明示「已截断」，不静默丢内容 |
| A3.3 | 生成标签时复用库内已有标签（取自 `core/index.rs`） | 不凭空造同义标签 |
| A3.4 | 生成/补全 `[[双链]]` 建议时，目标必须在库内存在或明确标注「待创建」 | 不产生无法解析的断链 |

### A4 库级管理动作

| # | 需求 | 验收标准 |
|---|---|---|
| A4.1 | 批量动作先产出**只读执行计划**（逐篇列出改动），用户勾选后执行 | 未确认前不写任何文件 |
| A4.2 | 批量打标签 / 规范命名建议 | 每篇可在计划里单独取消 |
| A4.3 | 生成 MOC（按标签或主题汇总为带 `[[双链]]` 的索引页） | 双链目标均可在库内解析 |
| A4.4 | 断链 / 孤儿笔记 / 空笔记清单（**优先用索引现算**，模型只做归类建议） | 结果可点击跳转 |
| A4.5 | 执行前逐文件快照，执行后给出「改了 N 篇，快照在…」 | 快照路径可见可取回 |

### A5 Skills

| # | 需求 | 验收标准 |
|---|---|---|
| A5.1 | 支持 Agent Skills 的 `SKILL.md`（`name` + `description` 必填） | 缺字段的 skill 被跳过并在设置里列出原因 |
| A5.2 | 发现位置：库内 `<vault>/.xink/skills/`、用户级 `~/Library/Application Support/xink/skills/` | 同名时库内优先 |
| A5.3 | skill 出现在命令面板（`AI:` 前缀）与 AI 菜单 | 展示 `name` 与 `description` |
| A5.4 | 注入由 xink 完成（清单 → 命中 → 加载正文），不依赖 CLI 自动发现 | HTTP 与 CLI provider 下行为一致 |
| A5.5 | 支持 skill 自带的 `references/` 按需加载（P1） | 正文声明后加载，不无条件塞上下文 |
| A5.6 | 可在设置里启停单个 skill | 停用后不出现在命令面板 |
| A5.7 | 内置动作与 skill 同构（内置动作也可用 `SKILL.md` 表达） | 二者在 UI 上无差别 |

### A6 上下文与检索

| # | 需求 | 验收标准 |
|---|---|---|
| A6.1 | 上下文三档：选中 / 整篇 / 多篇（用户勾选） | 选择界面与命令面板一致 |
| A6.2 | 全库动作先用 `search_files` + 索引召回候选 | 召回条目带路径与标题 |
| A6.3 | 字符预算可配（默认 12k 字符），超限截断并提示 | 面板明示截断 |
| A6.4 | 发给模型的内容不含应用数据目录等无关路径 | 隐私最小化 |

### A7 写入与撤销

| # | 需求 | 验收标准 |
|---|---|---|
| A7.1 | 所有会改内容的动作必须经 diff 预览（Q6） | 无「直接写盘」路径 |
| A7.2 | 接受前写快照到 `~/Library/Application Support/xink/ai-history/` | 目录存在且文件可打开 |
| A7.3 | 写入复用 `atomic_write`，并触发与手动保存一致的脏标记/索引更新 | 外部修改检测不误报 |
| A7.4 | 批量执行中可中止，已执行的保持已完成状态 | 不产生半篇写入 |

### A8 设置与可观测性

| # | 需求 | 验收标准 |
|---|---|---|
| A8.1 | 设置界面新增「AI」分类（元数据驱动，见 `ui/settings.rs`） | provider / 模型 / 超时 / 上下文上限 / 输出语言 / skills 列表 |
| A8.2 | 显示本次请求的用时与 token 用量（若有） | 面板底部一行状态 |
| A8.3 | 失败信息可读：区分网络 / 认证 / 限流 / 超时 / 解析失败 | 每种错误有对应文案 |
| A8.4 | 设置里可一键清空 AI 历史快照 | 目录被清理 |

### A9 交互入口

| # | 需求 | 验收标准 |
|---|---|---|
| A9.1 | 命令面板支持 `AI:` 前缀过滤动作与 skills | 与文件搜索共存，不互相干扰 |
| A9.2 | `Cmd+Shift+A` 开关编辑器下方的 AI 对话条 | 与现有键位无冲突 |
| A9.3 | 交互入口：编辑器下方的内嵌对话条（`Cmd+Shift+A`），含输入框与多轮历史 | 贴着编辑区、不遮挡正文；关掉后回到纯编辑 |

## 5. 配置项草案

挂在 `AppConfig` 新增的 `ai` 段（`src/core/config.rs:345`），全部带默认值与 `sanitize`：

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 总开关，关掉则所有 AI 入口不可用 |
| `provider` | `"openai_compatible"` | `openai_compatible` / `cli`（P1） |
| `base_url` | `""` | 整体可配，兼容智谱 `/api/paas/v4` 这类非 `/v1` 端点 |
| `model` | `""` | 必填，空则禁止发起请求 |
| `api_key_source` | `"keychain"` | `keychain` / `env` / `plain`（Q1） |
| `timeout_secs` | `60` | 流式静默超时 |
| `max_context_chars` | `12000` | 上下文字符预算 |
| `output_language` | `"auto"` | `auto` / `zh` / `en`（Q5） |
| `auto_apply` | `false` | 是否跳过 diff（Q6，建议始终 false） |
| `skills_enabled` | `true` | skill 总开关 |
| `disabled_skills` | `[]` | 停用的 skill 名 |

## 6. 数据落盘位置

| 内容 | 路径 |
|---|---|
| AI 配置 | `~/Library/Application Support/xink/config.json`（`ai` 段） |
| 凭据 | macOS Keychain（默认）；明文模式才进 config.json |
| 用户级 skills | `~/Library/Application Support/xink/skills/<name>/SKILL.md` |
| 库内 skills | `<vault>/.xink/skills/<name>/SKILL.md` |
| 修改快照 | `~/Library/Application Support/xink/ai-history/<时间戳>-<文件名>` |

库内 `.xink/` 需要在文件树里**默认隐藏**（与现有隐藏文件策略一致，`core/config.rs` 的隐藏开关），
且不被索引当作笔记（只有 `.md` 才进索引，`.xink/skills/**/SKILL.md` 是 `.md`，需在索引枚举时显式排除——
这是实现时要处理的一个具体点）。

## 7. 人工验收清单（M1 起逐条打勾）

1. 未配置 provider 时，触发任意 AI 命令 → 提示「未配置」，无任何网络请求。
2. 配置 DeepSeek（或 Ollama）→ 连接测试成功/失败提示正确。
3. 选中一段中文 → 「润色」→ 面板内文字逐步出现 → diff 正确 → 接受后编辑器内容更新、文件落盘。
4. 上一步的快照出现在 `ai-history/`，内容等于改前原文。
5. 丢弃结果 → 文件与编辑器内容均不变。
6. 请求中途取消 → 无残留回调，可立刻发起下一次。
7. 错 key → 认证错误提示；拔网线 → 网络错误提示；超时配置 5s 后触发 → 超时提示。
8. 整篇「生成标签」→ 优先复用库内已有标签。
9. 库级「断链检查」→ 结果与索引现算一致，可点击跳转。
10. 放一个自定义 skill 到库内 `.xink/skills/` → 命令面板 `AI:` 下可见 → 执行结果符合 skill 描述。
11. 关闭 AI 总开关 → 所有 AI 入口消失，应用其余功能不受影响。
