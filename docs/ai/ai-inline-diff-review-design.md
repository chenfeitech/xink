# 设计：编辑区内的行级 diff 评审

> 需求：AI 修改影响的每一行**同步呈现原始内容与修改后内容**、行内差异对比区分增删改，
> 每个变更块带「接受修订 / 拒绝修订」，**整个流程在编辑区内完成**，不依赖 AI 对话框。
> 前置：`docs/ai/ai-review-hunks-design.md`（评审条 + 按内容定位，已实施）、
> `src/core/ai/patch.rs`（块划分 / 定位 / 应用）。
>
> **状态：✅ 已确认并实施**（2026-10-27）。选型拍板如下：
>
> | 待拍板项 | 结论 |
> |---|---|
> | 方案 | **A 真插入式**：把 AI 新行真的写进编辑区再染色，视觉最接近 CodeBuddy/IDE |
> | 评审期只读 | **是**（`set_readonly(true)`，只挡用户打字、不挡程序化接受 / 拒绝） |
> | 老的评审条 | **退役**，功能并入编辑区顶部条，只留一套 UI |
> | 实施范围 | **R1–R5 一次做完** |
>
> 下面 §2 / §4 / §5 / §7 已按 A 方案重写；§1 的可行性结论仍然有效，
> 其中"编辑器文字流里插不了自定义块"正是按钮要放顶部条的原因。

## 1. 先说可行性：这套 crate 能做什么

调研方式：直接读 `~/.cargo/registry/src/*/gpui-base-0.8.0`（`Editor`/`EditorState` 在这里，
不是 gpui-pre）与 `gpui-pre-0.3.9`。

| 能力 | API | 结论 |
|---|---|---|
| 行 / 区间**底色染色** | `RangeDecoration::new(range).with_style(Fill).with_color(hsla)`（字节区间）；`create_range_decorations_collection` + `collection.set(...)`（`input/base/element.rs:866` 绘制，**项目已在用**） | ✅ 一等公民 |
| 区间 → 屏幕坐标 | `EditorState::range_to_bounds(&Range<usize>) -> Option<Bounds<Pixels>>`（`state.rs:4005`，未布局 / 不可见返回 `None`） | ✅ 有（软换行也准） |
| 行号 | `EditorState::set_line_number(bool)`（`state.rs:12074`），仅 `CodeEditor` 模式生效；插入行后自动连续 | ✅ 内建，不用自己画 |
| 评审期只读 | `set_readonly(true, cx)`（`state.rs:1274`）：只挡用户改，**不挡程序化 `replace`** | ✅ 正好 |
| 字节 ↔ 行 / 点 | `RopeExt::{line_start_offset, line_end_offset, slice_line, offset_to_point, point_to_offset}`、`state::{set_selected_range, replace}` | ✅ 齐全 |
| **在文本流里插自定义块**（新行 + 按钮） | 全仓搜 `insert_blocks` / `BlockProperties` / `BlockStyle` / `CustomBlock` 在 `gpui-base/src/input/**` 下 **0 命中**；`gpui-component::Editor` 只有 `h / appearance / bordered / disabled / readonly / tab_index / role / aria_label / context_menu / on_paste`，无块插槽 | ❌ **没有** |
| 自定义 gutter 内容 | gutter 内建但 `editor_gutter_bounds` 是 `pub(super)` | ❌ 插不进去 |
| `display_point ↔ point` 换算 | `display_map` 字段 crate 内可见，`display_point_to_point` 是 `pub(crate)` | ❌ 拿不到 |

**一句话**：染色 + 行号 + 只读 + 定位 四项 100% 可落地；
**"在编辑器文字流里插入一整块 UI"没有原生 API**。这决定了下面三个方案的差异。

## 2. 选型：A 真插入式（已拍板）

| | **A 真插入式（选它）** | B 覆盖层 | C 保持现状 |
|---|---|---|---|
| 做法 | 把 AI 新行**真的写进** `EditorState`，再给这些行上底色 | 正文不动，新行与按钮画在 `range_to_bounds` 定位的覆盖层 | 评审条留在编辑区下方 |
| 视觉相似度（vs CodeBuddy） | **最高**：改动就在正文里，滚动 / 软换行 / 行号全部天然正确 | 接近，但需每帧重算坐标 | 低（在看不到的地方） |
| 文档是否被污染 | **是**：评审期间正文含未接受的 AI 文本 | 否 | 否 |
| 行号漂移 | **是**：插入后后续块行号全变 | 无 | 无 |
| 撤销栈 | 被评审过程污染 | 干净 | 干净 |
| 工作量 | 大 | 中 | 0 |

选 A 是因为"视觉最接近 IDE"是本需求的主诉求；A 的三个风险各自都有兜底：

| 风险 | 兜底 |
|---|---|
| 文档污染 | 评审期间**禁止写盘**（`review_locks_saving`：自动保存与 `Cmd+S` 都被拦），只刷预览与装饰；另存了一份评审前快照 |
| 行号漂移 | **不用行号定位**：每块的锚是它自己的全部行文本（`ReviewBlock::review_lines`），每次处置都按内容 `locate_lines` / `locate_range` 重新找，处置顺序无关 |
| 回滚正确性 | 接受 / 拒绝都是**一次整块替换**（把块的行换成 `new_lines` / `orig_lines`），不是逐行增删，没有边界情况；另有「撤销整次评审」整体还原 |

按钮放哪：编辑器文字流里插不进自定义块（§1），所以"每块的接受 / 拒绝按钮"
放在**编辑区顶部条的块卡片**上，正文里只有真插入的行 + 染色；
点卡片标题会把编辑区选中到对应块。

## 3. 需求点 1：变更块的划分规则

沿用 `core/ai/patch.rs::hunks`（已实施、有 13 项单测），本次只补展示层的规则：

| 规则 | 取值 | 理由 |
|---|---|---|
| 聚合 | 相邻改动之间隔 **≤ `2 × context`** 行未变行就并成一块（`context = DEFAULT_CONTEXT = 2`，即间隔 ≤ 4 行） | 与 `git diff` 同思路：一行一改不该拆出十几个块 |
| 上下文 | 每块前后各带 `context = 2` 行 | 够定位语义，又不把整篇塞进覆盖层 |
| 最小粒度 | 一个块至少含 **1 行变更**；只有上下文的段不成块 | 否则会出现"没得接受"的空块 |
| 最大粒度（展示） | 单块 **> 8 行**时顶部条卡片只列改动行（`REVIEW_CARD_ROWS`）；正文里仍是全量，不折叠 | 卡片不能盖住半屏正文 |
| 最大块数 | `MAX_HUNKS = 50`，超出只显示前 50 块 | 与现状一致 |
| 修改 vs 删除 | 展示层把**一段连续改动里既有删又有增**的行整段标成"改"（`mark_pairs`，正文里旧行 warning、新行 success），只有单侧的才算"增 / 删"（新行 success / 旧行 danger） | 这是"清晰区分增删改"的关键：不配对的话，改一行会显示成"删了又加"，看不出是修改 |
| 定位 | **按内容**：块的锚是它自己的全部行文本（`ReviewBlock::review_lines`），用 `locate_range` / `locate_lines` 找，不按行号 | 接受第 3 块后前两块行号全变，行号方案必然错位 |

## 4. 需求点 2：差异的视觉呈现

**形态：上下对照（不是左右分栏）**，且对照发生在**正文内部**——
评审态文本 = 原文行 + 就地插在其下方的 AI 新行：

```
 ┌─ 编辑区顶部条（每块一张卡片）─────────────────────────┐
 │ 第 12 行起 · +1 -1      [接受修订] [拒绝修订]         │
 │ -   12  原文这一行要被改掉        ← danger（纯删）     │
 │ +        改后的这一行            ← success，无行号     │
 └───────────────────────────────────────────────────────┘
  12 │ 原文这一行要被改掉   ← 正文里，warning 淡底（"改"的旧行）
  13 │ 改后的这一行         ← 正文里，success 淡底（真插入的 AI 新行）
  14 │ 未改动的上下文       ← 不着色
```

| 元素 | 呈现 |
|---|---|
| 正文里的**待删行** | `RangeDecoration::Fill` + `danger` 淡底（孤立的删） |
| 正文里的**待改行** | `Fill` + `warning` 淡底（与紧邻的新行配对成"改"，与纯删区分） |
| 正文里的**新行** | `Fill` + `success` 淡底，紧随其原文行之后（上下对照） |
| 顶部条卡片 | 每块一张：`第 N 行起 · +a -r` + `接受修订` / `拒绝修订`；已处置的块只留状态标签，不再铺开细节 |
| 卡片里的行 | `- 行号 原文` / `+ （无号）新行`；新行**不带行号**（它不是原文里的行），用空位对齐 |
| 卡片超长 | 块 > 8 行时卡片只列改动行（`EditorPanel::card_rows`），避免盖住正文 |
| 行号 | 编辑区行号由控件内建连续编号（真插入 ⇒ 新行也有号）；"行号对齐"的锚点是卡片里的**原文行号** |
| 颜色来源 | `cx.theme()` 的 `danger` / `warning` / `success`，`opacity(0.18)`；**明暗两套都要验** |
| 已处理块 | 该块染色撤掉（只给未处置的块上色），顶部计数 `已接受 a · 已拒绝 b · 待处理 c` |

**为什么不用左右分栏**：编辑区宽度有限，左右分栏会把正文压成两半，且软换行下左右行对不齐。

## 5. 需求点 3：接受 / 拒绝后的状态更新

核心变化：**接受与拒绝都是"把这一块整体换成另一组行"的一次替换**，
不是逐行增删。锚点是块在评审态里的全部行（`ReviewBlock::review_lines`）：

| 环节 | 规则 |
|---|---|
| **接受** | `locate_range(text, 锚=new_lines)` → 一次 `replace_range` → 块标 `Accepted`。等价于"删掉该块的原文行" |
| **拒绝** | 换成 `orig_lines` → 块标 `Rejected`。等价于"删掉该块插入的 AI 新行"，原文逐字回来 |
| **定位失配** | `NotFound` / `Ambiguous(n)` ⇒ 标 `Stale("…")`，按钮换成提示文字，**绝不猜** |
| **块移除还是标记** | 已处理的块卡片只留状态标签、不再铺开细节，块仍留在 `AiReview` 里用于统计与"撤销整次评审" |
| **行号重算** | 每次都按内容重新定位（`patch::locate_lines` / `locate_range`），处置顺序**无关**（已测）；行号只是展示值，不参与定位 |
| **撤销栈** | 每处置一块 = `EditorState` 的一次编辑，理论上 `Cmd+Z` 可撤一块；**但评审期是只读的**，而框架的 `replay_history` 开头就查 `is_editable()`（`state.rs:3203`），所以评审期间 `Cmd+Z` 被拒。**"反悔"只走「撤销整次评审」**（用评审前的整篇快照），不依赖撤销栈 |
| **只读** | 进入评审 `set_readonly(true)`，全部处理完 / 手动退出 / 撤销时还原；程序化 `replace` 不受影响 |
| **未处理变更** | 顶部条常驻 `N 处待处理`；点「清除」时若还有未处置块，**先全部拒绝**（AI 新行是真的在正文里，直接收起会把它们留在笔记中），并在状态栏说明 |
| **写盘** | 评审期间（`resolved == false`）自动保存与 `Cmd+S` 都被拦，提示"先处理完"；全部处置完（`resolved = true`）才写盘并解除只读 |
| **脏状态** | 评审期间笔记是脏的（正文含插入行），与手动编辑同一套 `*` 提示 |

## 6. 测试计划（已落地）

自动化：

- `tests/core/ai/patch.rs`：`review_layout` 的就地插入、`-`/`+` 配对成"改"、
  孤立增 / 删不配对、块划分阈值（隔得远分成两块）、
  **全部接受 == AI 版 / 全部拒绝 == 原文**（`resolve_all` 模拟逐块处置）、
  `locate_lines` 的唯一 / 歧义 / 找不到
- `tests/ui/editor.rs`：评审状态机统计、`ReviewBlock` 两侧行、
  卡片的上下文裁剪与行号格式

人工（已进 `docs/ACCEPTANCE.md`）：

- [ ] 无选中执行"润色" → 正文里改动行就地插入并染色（删=红、改=黄、增=绿），顶部条出现逐块卡片
- [ ] 点「接受修订」→ 只有那一块变，其余逐字不变；该块染色撤掉
- [ ] 点「拒绝修订」→ AI 新行消失、原文回来，其余不变
- [ ] 处置后再 `Cmd+Z` → 能撤回这一块的处置
- [ ] 评审期间打字 → 打不进去（只读），但能选中复制
- [ ] 评审期间 `Cmd+S` / 等自动保存 → 被拦，状态栏提示"先处理完"（笔记不被写脏）
- [ ] 全部处置完 → 自动解除只读并写一次盘；顶部条变成统计行
- [ ] 点「撤销整次评审」→ 整篇回到评审前
- [ ] 还有未处理块时点「清除」→ 那些块按拒绝处理，AI 新行不残留
- [ ] 切明暗 / 换预置主题 → 三种底色仍可辨
- [ ] 接受前手改原文（先退出只读再改不现实，改用"AI 输出与原文对不上"的场景）→ 该块标失效，不盲改
