# 快捷动作可配置化

> 需求：把快捷动作精简为 6 项，并让它们可配置——支持新增，每项可配提示词，
> 请求模型时携带该提示词。
> 状态：已实施（2026-10-27）。决策由用户在需求澄清阶段拍板，见 §9。

## 1 现状（改动前）

| 事实 | 证据 |
|---|---|
| 8 个动作是 Rust 枚举，指令硬编码在 `instruction()` | `src/core/ai/prompt.rs:11-102` |
| 对话条按钮直接遍历枚举 | `src/ui/ai.rs` 原 `:1566` |
| 命令面板 `AI:` 入口同样遍历枚举 | `src/ui/command.rs` 原 `:383` |
| 「生成标签」的"复用库内标签"靠 `matches!(action, Action::Tag)` 硬判断 | `src/core/ai/prompt.rs` 原 `:141` |
| 落法（替换 / 插入）靠 `matches!(action, Continue \| Summarize \| Tag)` 硬判断 | `src/ui/ai.rs` 原 `:653` |
| `prefers_selection()` 定义了但没人调 | 全仓仅定义处一处 |
| 测试按 `all_actions().len()` 断言 | `tests/ui/command.rs:101,159` |

**由此推出的核心矛盾**：要"支持新增动作"，枚举必须换成数据；一旦换成数据，
上面三处**按枚举变体做的特判**（复用标签、落法、选中范围）全部失去落点。

## 2 目标 / 非目标

**目标**

- 内置动作精简为 6 项：润色、精简、翻译、改写标题、生成摘要、生成标签
- 动作是配置：可新增、可改提示词、可停用、可删除
- 每项的提示词随请求发给模型
- 旧 `config.json` 无迁移成本

**非目标**

- 不做动作的导入 / 导出（先手动加）
- 不把动作写成 `SKILL.md`（那是 skill 的形态，动作保持"一条指令"的轻量形态）
- 不做动作级的历史 / 用量统计

## 3 方案对比

| 方案 | 说明 | 结论 |
|---|---|---|
| **A. 动作全量配置化** | `ai.actions: Vec<AiActionConfig>`，内置 6 项只是默认种子 | ✅ **采用** |
| B. 只做提示词覆盖 | 保留枚举，配置里放 `HashMap<id, prompt>` 覆盖 | ❌ 不支持"新增动作"，不满足需求 |
| C. 动作配置化 + 内置项只读 | 内置 6 项不可改，只能新增自定义 | ❌ 用户明确要"可删除" |

## 4 数据模型与持久化兼容

```rust
pub struct AiActionConfig {
    pub id: String,          // 唯一；内置沿用 polish / condense / …
    pub name: String,        // 按钮与命令面板显示
    pub prompt: String,      // 发给模型的指令，支持 {{known_tags}}
    pub scope: AiActionScope,   // Selection（默认）| Whole
    pub apply: AiActionApply,   // Replace（默认）| Insert
    pub enabled: bool,
}
```

**为什么不只加 `prompt` 一个字段**：`scope` 与 `apply` 原先是硬编码的三处特判。
枚举消失后它们必须有落点，否则新建的动作会一律"替换整篇"——生成类动作会把
原文其余部分删掉。

**旧配置兼容**：`AiConfig` 带 `#[serde(default)]`，老 `config.json` 里没有
`actions` 字段时自动取 `Default`（即内置 6 项），**不需要迁移代码**。
反向也安全：老版本程序遇到新字段因同为 `serde(default)` 会忽略。

**校正（`AiConfig::sanitize_actions`）**：清掉空 id 与残缺条目、按 id 去重、
截断名字（32）与提示词（2000）、条数上限 32、名字空时用 id 顶上。

## 5 提示词占位符

`{{known_tags}}` —— 提示词里写了就把库内已有标签替换进去；库里还没有标签时
**整句剔除**（只删占位符会留下"优先从库里已有的标签中选择：；"这种残句）。

好处：任何动作都能复用库内标签，不再依赖"动作 id 恰好等于 tag"。
实现见 `src/core/ai/prompt.rs` 的 `strip_placeholder`。

## 6 交互

设置 → AI → 「快捷动作」：

```
快捷动作
提示词里写 {{known_tags}} 会带上库内已有的标签
─────────────────────────────────────────────────
润色     润色下面这段笔记：修正语病…      选中优先 替换 停用 编辑 删除
生成标签 为下面这篇笔记生成标签：…        整篇     插入 停用 编辑 删除
─────────────────────────────────────────────────
[+ 新增]  [恢复内置默认]
```

- 点「编辑」载入下方编辑区（名称 + 提示词），保存写回
- 「恢复内置默认」只**补回缺失的**内置项，不动用户改过的同名项
- 自定义动作 id 用 `custom-<毫秒时间戳>`；不做"名字转拼音"，没有可靠依赖

对话条按钮与命令面板 `AI:` 候选都从 `config(cx).ai.active_actions()` 读，
**执行时才按 id 重新查一次**——渲染到点击之间用户可能在设置里改过或删过。

## 7 测试

- `tests/core/config.rs`：默认 6 项、精简掉的两个不存在、旧配置无字段补默认、
  停用不生效、重复 id 去重、空 id 清理、名字空用 id 顶上
- `tests/core/ai/prompt.rs`：内置 6 项且 id 唯一、提示词随请求带出、
  `{{known_tags}}` 替换、库内无标签时整句剔除、没写占位符的不带标签

## 8 边界

| 场景 | 处理 |
|---|---|
| 用户删光所有动作 | 对话条按钮区为空，命令面板无 `AI:` 项；提示可「恢复内置默认」 |
| 执行时动作已被删 | 对话条提示"动作已不存在"；命令面板 `run_ai_action` 直接返回 |
| 提示词超长 / 条数超限 | `sanitize` 截断（2000 字符 / 32 条） |
| 新建动作默认是"替换" | 有评审条兜底：算不出 diff 会降级成插入 |
