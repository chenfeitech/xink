# xink — 需求规格说明书

> 基于 GPUI 的本地优先（local-first）Markdown 笔记桌面应用，对标 Obsidian 的基础能力。
> 应用名：xink。

## 1. 项目定位

在本机磁盘上用一个**普通文件夹**管理一批**普通 Markdown 文件**。不使用账号、不上云、
不把笔记转成专有格式——磁盘上的 `.md` 文件就是唯一真值（source of truth）。
应用只负责浏览、编辑和渲染，任何时刻删除应用，笔记依然是可读的纯文本。

**核心原则**：用户可以随时用任意外部编辑器（Vim / VS Code / Obsidian）改动同一批文件，
应用必须能感知并正确同步，而不是独占或破坏文件。

## 2. 术语

| 术语 | 含义 |
|---|---|
| **Vault（库）** | 一个被打开的本地文件夹，是一批笔记的根 |
| **Note（笔记）** | Vault 下的一个 `.md` 文件 |
| **Workspace（工作区）** | 应用级状态：当前库、打开的标签、布局、最近文件 |

## 3. 目标用户与场景

- 用 Markdown 记笔记的开发者/写作者，希望有一个**快、原生、启动即用**的本地编辑器
- 已有自己的文件组织方式（可能已在用 Obsidian），要求**不绑架文件格式**
- 典型会话：打开库 → 左侧浏览文件树 → 打开多篇笔记到标签 → 编辑 → 实时看预览 → 关闭

## 4. 功能需求

### P0 — MVP（本轮交付目标）

#### R1 Vault 与目录管理
| # | 需求 | 验收标准 |
|---|---|---|
| R1.1 | 通过系统文件对话框打开任意文件夹作为 Vault | 选中后左侧文件树完整展示目录结构 |
| R1.2 | 文件树支持目录展开/折叠，懒加载子目录 | 万级文件的库首屏 < 1s |
| R1.3 | 新建笔记 / 新建文件夹 | 立即出现在树中，磁盘上真实生成文件 |
| R1.4 | 重命名笔记与文件夹 | 磁盘同步重命名，打开的标签同步更新 |
| R1.5 | 删除笔记与文件夹（含非空目录二次确认） | 磁盘真实删除，打开的标签自动关闭 |
| R1.6 | 移动/拖拽笔记到其他目录 | 路径变更落盘 |
| R1.7 | 默认忽略 `.git`、`node_modules`、隐藏文件（可配置） | 这些目录不出现在树中 |

#### R2 Markdown 编辑
| # | 需求 | 验收标准 |
|---|---|---|
| R2.1 | 源码模式编辑 Markdown | 输入响应 < 16ms（无掉帧） |
| R2.2 | 防抖自动保存（停止输入 ~300ms 后写入），支持 `Cmd+S` 立即保存 | 保存后磁盘内容与应用一致 |
| R2.3 | 多标签页：可同时打开多篇笔记，支持切换与关闭 | 关闭未保存标签时有提示 |
| R2.4 | 大文件不卡：10MB 级笔记可正常编辑 | 使用 Rope 结构，不做全量字符串拷贝 |
| R2.5 | UTF-8 编码，中英文混排、CJK 光标定位正确 | 中文输入（IME）正常 |

#### R3 预览
| # | 需求 | 验收标准 |
|---|---|---|
| R3.1 | 编辑时预览实时更新（防抖） | 输入停止 ~300ms 内预览刷新 |
| R3.2 | 渲染 GFM：标题、粗斜体、删除线、列表、任务列表、引用、表格、代码块、分隔线、链接、图片 | 与 CommonMark/GFM 标准一致 |
| R3.3 | 图片支持本地相对路径与网络 URL | 本地图正常显示，网络图超时降级 |
| R3.4 | 预览区可独立滚动，与编辑区滚动大致同步 | 滚动平滑，无跳动 |
| R3.5 | 代码块有语法高亮 | 至少覆盖常见 10 种语言 |

#### R4 会话恢复
| # | 需求 | 验收标准 |
|---|---|---|
| R4.1 | 记住最近打开的 Vault 与打开的标签 | 重启后自动恢复到上次状态 |
| R4.2 | 记住窗口大小与面板布局（侧栏宽度、分屏比例） | 重启后布局一致 |
| R4.3 | 记录最近文件列表 | 启动页可快速进入 |

### P1 — 体验补齐（P0 完成后）

| # | 需求 |
|---|---|
| R5 | 双链 `[[笔记名]]`：可点击跳转，支持自动补全 |
| R6 | 反向链接面板：显示"哪些笔记引用了当前笔记" |
| R7 | 标签 `#tag`：解析、侧栏聚合、点击筛选 |
| R8 | 全文搜索 `Cmd+Shift+F`：跨库检索，结果可跳转 |
| R9 | 大纲（TOC）面板：按标题层级展示，点击跳转 |
| R10 | 命令面板 `Cmd+P`：模糊搜索文件名快速打开 |
| R11 | 明暗主题切换，跟随系统 |
| R12 | 常用 Markdown 快捷键（`Cmd+B` 加粗、`Cmd+I` 斜体等） |

### P2 — 明确不在本期范围

关系图谱（Graph View）、插件系统、日记与模板、PDF/HTML 导出、
所见即所得（WYSIWYG）编辑模式、移动同步、协作。

> **关于 WYSIWYG**：真正的所见即所得编辑成本极高（需自建块级编辑模型）。
> 本产品采用 **源码编辑 + 分屏实时预览**，这既符合 Markdown 用户习惯，也是务实取舍。
> 若未来要做，应作为独立大版本评估。

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| **性能** | 冷启动 < 2s；万文件库索引构建放后台不阻塞 UI；编辑 120 FPS 不掉帧 |
| **可靠性** | 写盘必须原子（临时文件 + rename），崩溃绝不产生半截文件；外部修改冲突走提示而非静默覆盖 |
| **数据安全** | 删除操作磁盘真实生效前需确认；不做任何云端上传 |
| **平台** | macOS 优先（当前开发环境），架构上保持 Windows / Linux 可编译 |
| **兼容性** | 与 Obsidian 的文件格式兼容（普通 `.md` + 相对路径图片），同一库可被 Obsidian 直接打开 |

## 6. 明确的非目标

- 不做账号体系、不做云同步
- 不引入数据库（不建索引库文件以外的专有格式；索引可随时重建）
- 不锁定用户（笔记永远是磁盘上的普通文件）
