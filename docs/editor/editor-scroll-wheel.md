# 编辑区鼠标滚动排查与修复

> 状态：**已实施，待人工验收**（2026-10-20）
> 范围：`ui/editor.rs`、`ui/preview.rs`、`core/sync.rs`
> 相关：`docs/preview/scroll-sync-design.md`（同步是本次滚动异常的主要来源）

## 1. 期望行为（先定标准）

| 维度 | 期望 |
|---|---|
| 方向 | 向下滚 → 内容上移（与系统一致）；横向不动（多行编辑区 `overflow_x_hidden`） |
| 速度 | 滚轮一格 = 系统给的 `ScrollDelta::Lines` × 行高；触控板 = `Pixels` 原样，**应用不再加任何倍率/加速度** |
| 边界 | 到顶/到底 clamp，不出橡皮筋；`scroll_size.height` 至少等于视口高，短文档滚不动是正确行为 |
| 底部 | **内容最后一行应能贴到视口底部**，后面不再有可滚的空白（写 Markdown 不需要代码编辑器那半屏留白） |
| 惯性 | 触控板惯性由系统持续投递事件（`NSEventPhase`），**应用不得在这期间写滚动位置** |
| 设备/系统 | 触控板 = `ScrollDelta::Pixels`（含惯性）；鼠标滚轮 = `ScrollDelta::Lines × 行高`，速度交给系统的"滚动速度"设置，应用不加倍率 |
| 不影响的交互 | 光标定位、拖选、双击选词、拖拽、IME 预编辑、点击链接/工具栏、滚动条拖动 |
| 与同步的关系 | 用户手势期间，**同步只能读、不能写**；手势停止 250ms 后恢复写入 |

## 2. 排查结论

先排除的几项（都不是原因）：

- **事件冲突**：项目没有挂自己的 `on_scroll_wheel` / `on_mouse_*`（全仓 grep 只命中 `file_tree.rs`），
  不存在两个 handler 抢事件。
- **容器配置**：`editor.rs` 里 `div().flex_1().min_h_0()` + `Editor::new(..).size_full()`，
  约束正确。（**隐患**：gpui-component 多行输入默认是 `h_auto`
  （`input/input.rs:706-709`），只因传了 `size_full()` 才被覆盖；一旦去掉，
  `scroll_size.height` 会被 `.max(bounds.size.height)` 抬到等于视口高 → 滚动静默失效。）
- **浏览器兼容性**：桌面应用（macOS + Metal），不涉及。

### 根因 1（主因）：滚动同步的写入压过用户滚轮

框架的 `set_scroll_offset` **不是立即生效**，只是种下 `deferred_scroll_offset`
（`gpui-base-0.6.4/src/input/base/state.rs:2811-2817`），而绘制时用的是 deferred
（`input/base/element.rs:671-679`）。也就是说：同一帧里"用户滚轮改的 offset"会被
"我们之前种下的 deferred"覆盖。

触发路径（都是本次同步重构引入的）：

1. `refine_pending`（软换行精调）每帧写一次 `set_scroll_offset`，最多 3 帧；
2. `apply_anchor` 在**软换行开启**时必然打开这个窗口（`editor.rs` 原逻辑），
   而软换行是默认开启的 → 每次"预览 → 编辑"同步都会强制写 1~3 帧；
3. 方向锁 200ms 过期后，预览可能反过来把编辑区拉到预览的位置。

表现：滚轮像被"吃掉"一格、滚到一半被拉回、触控板惯性期间明显卡顿/回弹。

### 根因 2：软换行下粗调目标系统性偏移

粗调按 `行号 × 行高` 算（`scroll_offset_for_line`），软换行下一个源码行占多个显示行
→ 目标偏上，要靠精调 1~2 帧修正 → 肉眼可见"跳一下"，也延长了 root cause 1 的写入窗口。

### 根因 3：回显容差（0.5 行）小于量化误差

`probe_top_line` 把锚点量化到整行边界，加上块内插值，往返误差可能超过 0.5 行
→ `is_echo` 判不掉 → 两端互相推 → 回弹。

### 根因 4：多余的一次重排

载入笔记时无条件 `set_soft_wrap(true)`（框架默认就是 true）会重算 display_map，
白白多一次布局，也让"刚载入"这个最容易出现位置错位的时刻更脆弱。

### 根因 5（**"偶尔无法滚动"的直接解释**）：最后一行之后的半屏空白

`EditorMode` 的 `CODE_EDITOR = true`（`gpui-base-0.6.4/src/input/editor/mod.rs:15`），
于是框架按**代码编辑器**的习惯给滚动区尾部加一段空白
（`empty_bottom_height`，`input/base/element.rs:377-390`）：

```rust
None => viewport_height.half().max(BOTTOM_MARGIN_ROWS * line_height)
```

默认 `None` → **半屏**。写 Markdown 时的表现是：内容明明已经到底了，还能继续滚半屏
（内容不动，只有空白在移动）→ 用户描述为"偶尔无法滚动内容"。它同时让编辑区与
预览区的可滚动范围对不上，是同步偏移的放大器。

### 根因 6：每帧探测 + 每帧推预览（顺滑度/跟手性）

- `probe_top_line`（软换行）每帧对 13 个候选行调 `range_to_bounds`；
- 每帧推送锚点 → 预览 `scroll_to` → 预览虚拟列表重排（还带代码块高亮）。

两者都压在主线程上，滚动时表现为掉帧、不够跟手。

### 已排除

- **"鼠标在某些位置滚不了"**：`on_scroll_wheel` 挂在编辑区**容器**上
  （`input/base/state.rs:4248`，容器是 `.flex_1()` + `h_full()`，含 padding 区），
  命中区覆盖整个可视区；滚动条是子件且未注册 wheel handler，事件会冒泡到容器。
  编辑区上方/下方也没有覆盖层。

## 3. 修改内容

1. **手势静默窗口**（`core/sync.rs` 新增 `GestureGuard`，两端复用）
   - 每帧比较"当前滚动位置"与"上一帧位置 + 我们自己写入的目标"：位置变了且不是我们写的
     → 判定为用户手势 → 打开 250ms 静默窗口（连续手势会续期）。
   - 窗口内：`apply_anchor` / `refine_pending` 一律**不写**（`refine_pending` 还会立刻放弃
     pending）；`tick` 仍然正常读取并推送给预览 —— 用户滚编辑区时预览照常跟随。
   - 250ms 覆盖触控板一次甩动的惯性尾巴。
2. **软换行粗调改用实测行高**：新增 `px_per_source_line`，滚动过程中用
   `Δ像素 / Δ行` 指数平滑学习，粗调目标 = `行号 × 实测每行像素`，一步到位，
   减少精调帧数与跳动。切换笔记时清零。
3. **回显容差放宽**：`Line` 从 0.5 行 → 1.5 行（覆盖整行量化 + 块内插值误差）。
4. **写后记账**：`apply_anchor` / `apply_ratio` / `refine_pending` / `settle_pending`
   写完都更新 `last_scroll_y`，避免把自己的写入误判成用户滚动（否则同步会被自己关掉 250ms）。
5. **预览侧对称处理**：同样加 `GestureGuard`（用户滚预览时编辑区不得回写）。
6. **去掉多余重排**：载入笔记时只在需要关闭软换行时才 `set_soft_wrap(false)`。
7. **关掉尾部空白**：载入笔记时 `set_scroll_beyond_last_line(Some(0))`
   （根因 5）。内容最后一行能贴到视口底部，不再有半屏空滚；
   顺带让编辑区的可滚动范围与"行高 × 行数"对齐，同步也更准。
8. **同步降频**：推送锚点改为每 2 帧一次（手势检测仍每帧），
   预览重排次数减半（根因 6）。
9. **探测减负**：软换行下的候选行从 13 个降到 7 个（前 2 后 4）。

## 4. 验证方式

**自动化**：`GestureGuard` 状态机 4 个单测（窗口开启 / 到期 / 连续手势续期 / reset），
`cargo test` 全绿（323）。

**分诊（先做这一步，能立刻区分"是不是同步导致的"）**

1. 设置 → 预览 → 关闭「同步滚动」；
2. 再滚编辑区：如果恢复正常 → 确认根因是同步写入，本次修复已覆盖；
   如果仍然异常 → 是框架侧或容器问题，请把现象描述给我（见下）。

**人工验收清单**

- [ ] **滚到文档末尾：最后一行贴在视口底部，后面没有可滚的空白**（根因 5 的验收点）
- [ ] 内容不足一屏时滚不动：属正确行为，不是 bug
- [ ] 鼠标停在编辑区**左侧行号区 / 右侧滚动条 / 四角**上滚轮：都能滚
- [ ] 滚轮向下/向上滚：方向正确、连续、不跳
- [ ] 快速甩动触控板：惯性顺滑，松手后不被拉回（**核心**）
- [ ] 滚到顶/滚到底：停在边界，不出现空白/回弹
- [ ] 滚动过程中点击定位光标、拖选文字：不受影响
- [ ] 中文输入法候选框出现时滚动：不打断预编辑
- [ ] **拖动滚动条**：能拖、跟手；拖动过程中预览跟随且不被反向拉回
- [ ] 触控板两指上下滑：方向与系统一致，松手后惯性自然衰减（不被打断/回弹）
- [ ] 长文档（几百行 + 代码块）快速滚：不掉帧、不卡顿
- [ ] 开着"同步滚动"滚编辑区：预览跟随（静默窗口只挡写入，不挡推送）
- [ ] 滚预览时编辑区跟随；交替滚动时最后一次手势生效
- [ ] 勾选/取消「软换行」：滚动位置不乱跳
- [ ] 打开 HUD（`preview.debug_scroll_sync`）：停止滚动后 `Δ` 收敛

**仍未排除的框架侧疑点**（若上述第 2 步仍异常，从这里查）：
`input/base/element.rs:226-243` 的滚动条 element 会在 prepaint 与 paint 之间把
`scroll_handle` 反写回 snapshot 值；正常帧序下不会触发，但它是第二个可能的
"滚轮被回退"点，届时需要换成框架内修复或在应用层绕开。
