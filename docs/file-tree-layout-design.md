## 1. 现状与问题

节点渲染的现有写法（`src/ui/file_tree.rs`）：

```722:757:/Users/helightxu/chenfei/rustgpui/src/ui/file_tree.rs
let mut row = div()
    .flex()
    .items_center()
    .gap_1()
    ...                                  // 字体取配置
if is_dir { ...icon(ChevronDown) + icon(FolderOpen)... }
else if is_image_path(&path) { row.child(div().w(icon_px)).child(icon(FileImage)) }
else { row.child(div().w(icon_px)).child(icon(FileText)) }

let name = div().child(item.label.to_string());   // ← 问题所在
row = row.child(name);

ListItem::new(("file-tree-item", ix))
    .pl(px(6. + depth as f32 * 16.))              // ← 缩进是固定像素
    .child(row)
```

**层级缩进本身是稳定的**（`pl` 为固定像素 `6 + depth × 16`，不随面板宽度变化）。
真正导致"跳跃、错位"的是行内元素在 flex 下的收缩行为：

| # | 成因 | 表现 |
|---|---|---|
| P1 | 文件名 `div()` 未设 `min_w_0` / 未限宽，长文本按内容宽度参与布局 | 名字越长，行越宽；行宽超过面板时出现横向溢出或把行撑开 |
| P2 | 图标与占位 `div().w(icon_px)` **未设 `flex_none()`** | 容器可用宽度不足时，flex 会**压缩这些固定尺寸元素**，图标间距被挤窄 |
| P3 | `row` 未设 `w_full()` / `min_w_0()` / `overflow_hidden()` | 行宽由内容决定，不同行的宽度不一致；面板宽度变化时收缩比例随之变化 |
| P4 | 文件名无截断策略 | 超长名既不被裁剪也不换行，是"撑开"的直接来源 |

结果：**同一层级下，文件名长短不同 → 起始列位置不同**；面板宽度变化时收缩比例变化 → 视觉上"跳动"。

## 2. 目标 / 非目标

**目标**

- 各层级的缩进量与名称起始列**恒定**，不随文件名长度变化
- 面板宽度变化时，布局不跳动（只表现为名称显示范围变化）
- 文件名超长时截断显示，不撑开行、不产生横向滚动
- 目录 / 文件 / 图片三类节点的图标列严格对齐

**非目标**

- 不改层级缩进的算法与数值（保持 `6 + depth × 16`）
- 不做文件名折行（多行会破坏"一行一节点"与对齐）
- 不做横向滚动查看长名（截断 + tooltip 足够）
- 不改数据层（扫描、监听、id）

## 3. 方案

| # | 改动 | 作用 |
|---|---|---|
| S1 | 行容器 `row`：`.w_full()` + `.min_w_0()` + `.overflow_hidden()` | 行宽恒等于可用宽度，不因内容变化；内部允许收缩；超出部分裁剪 |
| S2 | 所有图标与占位 `div().w(icon_px)`：加 `.flex_none()` | 固定尺寸元素**不被压缩**，图标列位置恒定 |
| S3 | 文件名容器：`.flex_1()` + `.min_w_0()` + `.overflow_hidden()` + 文本截断 | 名称占满剩余空间；超长时截断（末尾省略号），既不挤压兄弟也不撑开行 |
| S4 | `ListItem`：`.min_w_0()` + `.overflow_hidden()` | 整行不溢出父容器，杜绝横向滚动与宽度抖动 |

**截断方式**：框架无 `.truncate()`（gpui-pre 0.3.5 未暴露），因此采用
`.whitespace_nowrap()`（`styled.rs:82`）+ `.overflow_hidden()` 硬裁剪——尾部直接切，**没有末尾省略号**。
这是当前框架下的唯一选择；将来若暴露 `truncate`，改一行即可升级为省略号。

**为什么"截断"而不是"折行"或"允许横向滚动"**：

- 折行 → 一个节点占多行，层级关系立刻变得难读，且行高不一致会引发新的跳动；
- 横向滚动 → 每次滚动都会改变可见起点，与"稳定一致"的目标相悖；
- 截断 + 鼠标悬停提示 → 宽度变化时只有"显示多少"变化，**列位置始终不动**。

## 4. 约束

| # | 约束 | 说明 |
|---|---|---|
| C1 | 缩进数值保持不变 | `pl = 6 + depth × 16`；如需可配置应另立需求，不在本次范围 |
| C2 | 图标尺寸仍取自 `basic.icon_size` | 改配置即时生效的既有行为不能破坏 |
| C3 | 字体仍取自 `basic.tree_font` | 同上 |
| C4 | 不引入新依赖 | 只用框架已有布局 API |
| C5 | 目录 / 文件 / 图片三类仍严格同列 | 占位 `div` 的宽度与图标一致（`icon_px`） |

## 5. 验收

1. 同一层级下，文件名长短差异很大时，**名称起始列完全对齐**
2. 拖动面板宽度（由窄到宽、由宽到窄）过程中，图标列与缩进**不发生位移**
3. 极长文件名（如 80+ 字符）→ 末尾截断显示，行不撑开、**无横向滚动条**
4. 深层节点（depth ≥ 4）在窄面板下缩进仍正确，不出现负缩进或重叠
5. 目录 / 文件 / 图片三类节点的图标左边缘对齐
6. 改"图标大小 / 目录树字号"后仍对齐（C2/C3 不回退）
7. 悬停长文件名能看到完整名称（若实现了 tooltip）
