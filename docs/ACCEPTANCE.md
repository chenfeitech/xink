## 1. 编辑区 Markdown 语法高亮

## 3. 编辑区滚轮

来源：`docs/editor/editor-scroll-wheel.md` §4

**前置分诊**（先做这一步，能省一半时间）：设置 → 预览 → 关掉「同步滚动」→ 再滚编辑区。
恢复正常 ⇒ 根因是同步写入；仍异常 ⇒ 框架侧 / 容器问题。

- [ ] **滚到文档末尾：最后一行贴在视口底部，后面没有可滚的空白**
- [ ] 内容不足一屏时滚不动：正确行为，不是 bug
- [ ] 鼠标停在行号区 / 滚动条 / 四角上滚轮：都能滚
- [ ] 上下滚：方向正确、连续、不跳
- [ ] 快速甩动触控板：惯性顺滑，松手后**不被拉回**（核心）
- [ ] 滚到顶 / 滚到底：停在边界，不出现空白或回弹
- [ ] 滚动中点击定位光标、拖选文字：不受影响
- [ ] 中文输入法候选框出现时滚动：不打断预编辑
- [ ] **拖动滚动条**：能拖、跟手；拖动中预览跟随且不被反向拉回
- [ ] 触控板两指上下滑：方向与系统一致，惯性自然衰减
- [ ] 长文档（几百行 + 代码块）快速滚：不掉帧
- [ ] 开着「同步滚动」滚编辑区：预览跟随
- [ ] 滚预览时编辑区跟随；交替滚动时最后一次手势生效
- [ ] 勾选 / 取消「软换行」：滚动位置不乱跳
- [ ] 开 HUD（`preview.debug_scroll_sync`）：停止滚动后 `Δ` 收敛

## 13. AI 研发流水线（rules + skills 体系，M1–M4）

来源：`docs/ai-rd-pipeline-design.md`、执行计划 `docs/exec-plans/ai-rd-pipeline.md`

> 这一节验的不是应用功能，而是**AI 是否真的按流水线干活**。
> 全部靠"提一句需求看它怎么反应"来验，不看代码。

### 13.1 规则是否被加载（M1）

- [ ] 新开一个会话，随口说「我想加个功能」——AI 是否先走需求澄清，
      **而不是直接去改 `src/`**
- [ ] 改 `src/core/*.rs` 时，AI 是否引用了 `04-notes-domain` 的规则内容
      （说明 globs 生效）
- [ ] 动 `Cargo.toml` 时，AI 是否引用了 `01-gpui-stack` 的版本铁律

### 13.2 需求澄清（M2）

- [ ] 提一个真实需求 → AI 先查代码，结论**附 `文件:行号`**，不写"应该是"
- [ ] 模糊点被**一次性打包**成表格提问（不是挤牙膏式追问），每条带默认建议
- [ ] 你能用「都按默认」一句话采纳
- [ ] 产出 `docs/<slug>-requirements.md` 且含「非目标」章节

### 13.3 方案设计（M2）

- [ ] 设计文档给出 **≥2 个方案**并写明被否决方案的理由
- [ ] 文档「开放问题」里需你拍板的项被单独列出
- [ ] **AI 停在设计确认这一步等你**，没有自己往下写码

### 13.4 计划与实施（M3）

- [ ] 确认设计后，AI 拆出任务表（有 `T-n`、依赖、验收方式）
- [ ] 提真实缺陷（现象明确、改法唯一）→ AI 走豁免路径直达实施，
      **事后补了「现象 / 根因 / 改法」三行说明**
- [ ] 每次提交前 AI 都跑了四条命令并把**实际输出**贴进状态文件
      （不是只写"通过"）

### 13.5 测试与交付（M4）

- [ ] 新增 `core/` 逻辑都有对应 `tests/` 文件并挂载
- [ ] 边界九项被逐条标注「已测 / 要人工 / 不适用」，留空视为未做
- [ ] 交付时 AI 明确告诉你「这些需要你亲自看」，人工项进了 `ACCEPTANCE.md`
- [ ] **AI 没有替你在 `ACCEPTANCE.md` 打勾**
- [ ] `docs/INDEX.md` 状态与代码实际一致（新文档已登记）

### 13.6 状态文件（贯穿）

- [ ] `docs/exec-plans/<slug>.md` 能被新会话读懂并恢复进度
      ——**换一个会话继续做同一需求**，看 AI 是否接得上
- [ ] 门禁表里的命令输出摘要可事后核对

不通过怎么办：回到 `docs/ai-rd-pipeline-design.md` 定位是规则缺失（rules）
还是流程缺失（skills）；规则问题改 `.codebuddy/rules/`，

## 14. 预览区向左伸展（遮蔽编辑区）

来源：`docs/preview-extend-design.md`、执行计划 `docs/exec-plans/preview-maximize.md`

> 这条功能**没有自动化测试**——走的是框架 Zoom，状态由 `DockArea` / `TabGroup`
> 持有，只能跑起来看。

**实现形态（验收前先看清它是什么）**

- 触发元素：预览区标题**最左侧**的按钮（在「预览」两字之前），id `preview-extend-toggle`
- 展开方向与尺寸变化：不是"预览变宽"，而是预览所在的 **tab group 顶掉整个 dock 区域**，
  从右栏的 420px 变成铺满窗口（编辑区被压到不再渲染）
- 遮蔽层级：`DockArea::render` 命中 `zoomed_view()` 后**不再绘制 Left/Center/Right 三栏**
  （`dock_area.rs:1565-1593`）→ **编辑区被遮，左侧文件树也一并被遮**
  （这是 Zoom 的固有语义，也是本轮要拍板的点，见下）
- 恢复条件：① 再点同一按钮 ② 切换 / 重载布局（`load()` 清 zoom）
  ③ 伸展中的 group 被关闭或拖走（框架自动解除）

- [ ] 命令面板 `AI:` 前缀过滤出来的也是这 6 个
- [ ] 设置 → AI → 快捷动作：6 项都在，能看到各自的提示词

- [ ] 新增的动作点下去，模型收到的指令确实是刚填的那条提示词（看对话条里压的 user 块）

- 若**旧配置升级后动作全没了** → 检查 `AiConfig` 的 `#[serde(default)]` 是否还在
