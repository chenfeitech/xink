# 预览排版优化 — 设计方案

> 状态：**待确认**（2026-10-12）· 确认后再开发
> 范围：`src/ui/preview.rs`（预览容器与 `TextView` 样式）

---

## 1. 现状

预览由 `TextView` 渲染，当前可控项只用了其中很少一部分：

```rust
// preview.rs 当前
.font_family(font.family)                      // 配置驱动
.text_size(px(font.size))                      // 配置驱动
.line_height(px(font.size * font.line_height)) // 配置驱动
.max_w(px(cfg.preview.max_width)).mx_auto()    // 配置驱动（0 = 不限）
.px_4().py_2()                                 // 硬编码：左右 16px、上下 8px
```

**问题**：段间距、标题层级、代码块与表格的内边距全部用框架默认值，
正文之外的留白偏小，整体显得"挤"；标题与正文的大小关系也偏弱，层级不清。

## 2. 框架能力（已核实，可放心使用）

`TextView::style(TextViewStyle)`（`text_view.rs:43/227`），`TextViewStyle` 提供：

| 能力 | 方法 |
|---|---|
| **段间距** | `with_paragraph_gap(Rems)` |
| **标题基准字号** | `with_heading_base_font_size(Pixels)` |
| **标题层级函数** | `with_heading_font_size(Fn(u8, Pixels) -> Pixels)` |
| 代码块样式 | `with_code_block(StyleRefinement)` |
| 行内代码 | `with_inline_code(HighlightStyle)` |
| 表格 / 表头 / 单元格 | `with_table` / `with_table_head` / `with_table_cell` |
| 颜色（前景/弱化/链接/选区/代码底/边框） | 各自 `with_*` |
| 从主题派生（保持明暗一致） | `from_theme(&Theme)` |

## 3. 优化项

### 3.1 间距与留白

| 项 | 当前 | 建议 | 说明 |
|---|---|---|---|
| 容器左右内边距 | 16px | **24px** | 正文两侧留白更足，不再贴边 |
| 容器上下内边距 | 8px | **16px** | 顶部不顶头、底部有余量 |
| 段间距 | 框架默认 | **约 0.9rem（≈14px）** | 段落之间明显分开，是"不挤"的关键 |
| 代码块内边距 | 框架默认 | 增加 padding + 圆角 | 与正文区分更清晰 |

### 3.2 排版层级

- 标题基准字号：按正文字号推导，保证**相对关系**而非写死像素；
- 层级阶梯建议（相对正文）：
  - h1 ×1.8、h2 ×1.5、h3 ×1.25、h4 ×1.1、h5 ×1.0、h6 ×0.95
- 标题与正文之间留出比段间距更大的空隙，形成视觉分组。

### 3.3 可读性

- 行高：建议默认 **1.7** 左右（长段落阅读更舒适）；仍可由配置调整。
- 正文最大宽度：默认 0（不限）在宽屏上会导致**行长过宽**，建议给出更合理的默认值
  （约 720–780px），用户仍可在设置里改或关。

### 3.4 视觉平衡

- 正文区居中（`mx_auto` 已有），配最大宽度后两侧留白对称；
- 图片宽度沿用既有 `image_width_percent`，不额外改；
- 表格单元格加内边距，避免文字贴线。

### 3.5 不同屏幕尺寸

- 最大宽度用 `max_w(px(x))`：容器窄于 x 时自动收缩，**天然自适应**；
- 内边距在窄面板下会显得占比过大 → 窄屏时降一档（如 24px → 16px），
  按可用宽度分档（阈值待实测确定）；
- 字号/行高由配置控制，用户可自行适配自己的屏幕。

## 4. 是否新增配置项

**建议：不新增**，只把默认值调到更舒适。

理由：排版属于**设计决策**，不是用户偏好；且我们刚清理过"死配置"，
应避免为观感细节再堆配置项。已有的 `font` / `line_height` / `max_width`
足够用户微调。

> 若你希望"段间距"或"标题大小"也可调，我可以再加——但那需要同时补
> 设置项、单测与文档（即项目规定的"五件套"）。

## 5. 验收

1. 段落之间有明显但不夸张的间隔，长文读起来不挤
2. 标题层级一眼可辨（h1/h2/h3 大小差异明显）
3. 正文两侧留白充足，宽屏下行长不至于过长
4. 代码块、表格与正文区分清晰
5. 把预览面板拖窄 → 内边距与行长自适应，无横向滚动
6. 明暗主题下观感一致

## 6. 风险

| # | 风险 | 处置 |
|---|---|---|
| R1 | 段间距/标题数值偏主观 | 先给建议值，你验收后微调（改数值成本极低） |
| R2 | 改默认值影响已有用户观感 | 属纯视觉调整，不影响笔记内容 |
| R3 | 窄屏分档阈值需实测 | 实施时以实际宽度试出阈值 |

## 8. 追加决策：新增「布局密度」三档（2026-10-12）

需求：预览界面新增菜单，提供**紧凑 / 适中 / 宽松**，默认**适中**。

### 8.1 参数表

密度只管**版面松紧**；字体与行高仍由既有配置控制（避免两套设置互相覆盖）。

| 档位 | 左右内边距 | 上下内边距 | 段间距 | 标题基准（×正文字号） | 正文最大宽度 |
|---|---|---|---|---|---|
| 紧凑 Compact | 16px | 8px | 0.55rem | ×1.45 | 960px |
| **适中 Normal（默认）** | 24px | 16px | 0.90rem | ×1.70 | 780px |
| 宽松 Relaxed | 32px | 24px | 1.30rem | ×1.90 | 680px |

标题层级在基准上递减：h1 = base、h2 ×0.87、h3 ×0.77、h4 ×0.68、h5 ×0.62、h6 ×0.58。

### 8.2 与既有 `max_width` 的关系

`preview.max_width` 是用户显式设置（默认 0 = 不限）。
**用户显式设置优先**：非 0 时用用户的值，为 0 时才用当前档位的默认宽度。
这样既保留既有配置的意义，又不会让档位失效。

### 8.3 实施结果（2026-10-12）

- `core/config.rs`：新增 `PreviewDensity`（compact / normal / relaxed，**默认 normal**）
  与 `PreviewConfig.density`；`PreviewDensity::layout()` 给出三档版面参数（纯函数）。
- `ui/preview.rs`：顶部新增密度菜单（`DropdownButton`），改动走 `update_config`
  （落盘 + 刷新窗口，与设置页一致）；按档位应用
  `paragraph_gap`、标题基准字号与层级缩放、容器内边距、正文最大宽度。
- `ui/settings.rs`：设置页「预览 · 排版」同步新增该选项。
- 排版样式用 `TextViewStyle::from_theme(&cx.global::<BaseTheme>())` 构造——
  注意 `from_theme` 要的是 **gpui_base** 的 Theme（全局），与
  `cx.theme()` 返回的 gpui_component::Theme 是不同类型；`from_colors` 为私有，不能用。
- 单测 5 个（默认适中、JSON 小写、往返、三档松紧单调、取值回落），**140 passed**。

**待人工验收**：切换三档时留白/段间距/标题大小明显变化且即时生效；
`max_width` 显式设置时优先于档位；明暗主题下观感一致。

### 8.4 密度菜单位置调整（2026-10-12）

反馈：密度菜单单独占一行，希望与面板右上角的"预览"同一行。

做法：把菜单从内容区的独立工具条移进 `PreviewPanel::title()`，
与"预览"文字用 `flex + items_center + gap_2` 排在同一行：

- 水平对齐：`items_center`；间距一致：统一由 `gap_2` 控制（不再各写 padding）；
- 菜单外层加 `.occlude()`，避免点菜单时顺带触发标签选中；
- 不同尺寸：菜单是 `flex_none` 的固定小按钮，标签栏变窄时不会把文字挤到换行
  （文字侧可随可用空间收缩，菜单保持不变形）。

内容区因此少了一行工具条，纵向空间全部留给正文。
