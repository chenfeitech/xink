# 设计：索引驱动的面板 —— 反链（P1-T10 / R6）、标签（P1-T11 / R7）

## 1. 现状与问题

| 事实 | 证据 |
|---|---|
| 索引已提供 `backlinks(path)`：`(来源, 行号, 目标文本)` | `core/index.rs`（T6，已单测） |
| 索引已提供 `tags()` / `notes_with_tag()` | 同上 |
| 跳转能力已有：`open_note_at(path, line)` | T8 |
| 右侧 dock 目前有「预览」「大纲」两个 tab | `src/app.rs:605` |
| 当前活动笔记可从 `AppState.tabs.active()` 取到 | `src/ui/tabs.rs` |

两个面板的差异只在"取什么数据"，其余（位置、刷新时机、点击行为）完全一致，因此合并设计。

## 2. 目标 / 非目标

**目标**

- 反链面板：列出"哪些笔记引用了当前笔记"，点击跳到引用所在行
- 标签面板：聚合库内标签与计数，点击展开带该标签的笔记列表，再点跳转

**非目标**

- 反链**不显示上下文片段**：索引不存正文（T6 §3 决定），渲染时读文件属于"在 render 里做 IO"，
  违反规则；改为显示"来源笔记标题 · 第 N 行"
- 不做"未链接提及"（需要正文匹配，同样受制于不存正文）
- 标签不做层级树（`#a/b` 只作为独立标签名展示）

## 3. 方案概述

**数据来源**：一律读索引（`AppState.notes`），不自己扫盘。

**刷新信号**：面板自己不轮询，订阅两个事件源：

| 事件 | 来源 | 覆盖 |
|---|---|---|
| `IndexChanged` | `NoteIndex`（新增 `EventEmitter`） | 保存、外部增删、切库重建 |
| `ActiveDocChanged` | `AppState.preview`（已有） | 切换当前笔记 |

订阅回调只做 `cx.notify()`，数据仍在 `render` 里读——避免在回调里复制数据。

**当前笔记**：`AppState.tabs.active()`。不另设"当前笔记"状态，避免第二处真值。

**点击**：一律 `tabs::open_note_at(path, Some(line))`，与大纲同一出口。

## 4. 面板布局

右侧 dock 与「预览」「大纲」同组 tab（`MAIN_DOCK_VERSION` 每次新增面板递增）：

| tab | 内容 |
|---|---|
| 反链 | 来源笔记标题 + `第 N 行`；空态"还没有笔记引用它" |
| 标签 | `标签名 (n)` 列表；点击展开该标签下的笔记 |

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 索引未构建完 | 列表为空，显示"正在构建索引…"之后自然填充 |
| 当前是数据文件 / 没有打开笔记 | 反链显示"没有打开的笔记"；标签面板不受影响（库级数据） |
| 引用来源已被删除 | 索引增量更新时剔除，列表随之消失 |
| 同名笔记 | 反链按路径区分，显示标题可能出现同名，行号可区分 |
| 标签大小写 | 索引已归一为小写展示 |

## 7. 人工验收清单

**反链**
- [ ] A 引用 B，打开 B → 反链列出 A，并显示行号
- [ ] 点击 → 跳到 A 的引用行；A 已打开则只激活
- [ ] 删除 A 里的引用并保存 → 反链条目消失
- [ ] 打开没人引用的笔记 → 空态

**标签**
- [ ] 面板列出 `#tag` 与出现次数
- [ ] 点击标签 → 展开该标签下的笔记，再点打开
- [ ] 大小写不同的同一标签只算一个
