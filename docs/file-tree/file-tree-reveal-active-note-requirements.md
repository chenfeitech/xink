# 目录树跟随活动笔记 — 需求文档

> 文档状态：待实现（2026-10-23）
> 涉及模块：`src/ui/file_tree.rs`（FilesPanel）、`src/ui/editor.rs`（EditorPanel::set_active）
> 关联能力：gpui-base 0.8.0 `TreeState::reveal_item`

---

## 1. 背景与目标

在编辑区切到另一篇笔记时，左侧文件树仍停在上一次点击的位置。如果这篇笔记藏在
未展开的目录里，用户看不到"我现在在哪"，只能自己在树里翻找。

**目标**：切换活动笔记时，文件树自动定位到该笔记所在节点——未展开的祖先目录自动
展开、节点选中、并滚动到可见。

## 2. 触发定义（关键）

**触发点只有一个：在编辑区点已存在的标签页。**

即 dock 上切换标签时触发，对应 `EditorPanel::set_active`（`src/ui/editor.rs:1867`）。
从文件树点击、命令面板、搜索、大纲、反链、标签、双链跳转打开笔记，
最终也会经过标签切换，因此一并被覆盖。

**不触发**：

- 编辑区获得焦点但活动笔记没变
- 文件树自身的扫描刷新
- 预览区滚动、光标移动

## 3. 功能需求

| # | 需求 | 验收标准 |
|---|---|---|
| FR1 | 展开目标笔记所有未展开的祖先目录 | 笔记藏在三层深的折叠目录里也能一路展开 |
| FR2 | 选中目标节点 | 节点呈选中态，与鼠标点选的视觉一致 |
| FR3 | 把目标节点滚动到可见 | 长目录树下目标不在视口内时滚进视口 |
| FR4 | **允许覆盖文件树当前的选中项** | 用户在树里选中了别的节点，切标签后选中被切到活动笔记 |
| FR5 | 活动笔记未变时不重复同步 | 同一篇笔记重复触发只做一次，不反复抢选中 |
| FR6 | 目标不在树里时静默跳过 | 不报错、不弹提示、不改动当前选中 |
| FR7 | 树还没扫描完时，延迟到扫描完成后补一次 | 冷启动恢复多个标签后，树扫完即定位到活动笔记 |

## 4. 边界

| 场景 | 处理 |
|---|---|
| 笔记不在当前库（跨库 / 库外文件） | 静默跳过 |
| 笔记在 `.git` / `node_modules` / `target` 等永远跳过的目录 | 静默跳过（这些目录本就不进树） |
| 切换库 | 切库会关闭不属于该库的标签；不额外处理 |
| 关闭标签后焦点落到邻居标签 | 跟随（dock 会触发 `set_active`） |

## 5. 非目标

- **不做反向同步**：在树里点文件就打开笔记是既有行为，本需求不改。
- 不改文件树的刷新策略与展开状态的持久化（`docs/file-tree/file-tree-incremental-refresh-design.md` 已覆盖）。
- 不因为"用户刚在树里操作过"而让位：FR4 明确支持抢走选中。
