# 测试规范

> 测试**放在哪、怎么挂**见 `docs/TESTS.md`（`tests/` 镜像 `src/`，用 `#[path]` 挂载）。
> 本规则只定义「该测什么、测到什么程度」。
> 门禁见 `07-quality-gates.md` G5。

## 1 覆盖底线

| 层 | 底线 |
|---|---|
| `core/` 新增模块 | 必须建 `tests/<层>/<模块>.rs` 并 `#[path]` 挂载 |
| `core/` 新增 `pub` 函数 | 正常路径 + ≥1 个边界（空 / 非法 / 超大 选一） |
| 涉及文件系统 | 必须 `tempfile`，**绝不**污染真实用户目录 |
| 涉及写盘 | 必须有「写失败」路径的用例 |
| `ui/` | 只测两类：查表类静态数据、纯函数与纯状态迁移 |

**UI 渲染与一切需要 `App` / `Window` / `Entity` 的测不了**（`docs/TESTS.md` 已核实：
全仓从未用过 `TestAppContext`）。不要硬凑测试。

## 2 边界九项

逐条标注「已测 / 要人工 / 不适用」，不适用须注明理由：

空输入 / 超大输入 / 非法路径 / 并发写 / 外部程序改文件 / 崩溃后半截文件 /
多库切换 / 隐藏与忽略文件 / 非 UTF-8

具体判据见 `.codebuddy/skills/requirement-clarify/references/boundary-checklist.md`。

## 3 三类「测不了」的处理原则

| 类别 | 做法 |
|---|---|
| 写真实 `app_data_dir()` / 发真实 HTTP | **抽出纯规则函数测**，函数本身留人工验收 |
| 状态迁移在 `cx.listener` 闭包里 | **仅当出过 bug** 才为可测性重构 |
| 渲染 / 手感 / 着色 | **不硬凑测试**，登记到 `docs/ACCEPTANCE.md` |

抽函数只做**原样搬移**（3~15 行、行为不变），**不为测试改设计**。

## 4 命名与断言

- 测试名 `should_xxx_when_xxx`，或在注释里写清场景（`03-rust-code-style.md` §6）
- 一个测试只验一件事
- 断言要具体：`assert_eq!(got, expected)`，**不要** `assert!(result.is_ok())` 这类空断言
- 测试注释里标关联需求：`// R-3: 空库时搜索返回空列表`

## 5 禁止

- 测试里写死真实用户路径（`~/`、`app_data_dir()`）
- 测试依赖执行顺序或全局状态
- 为提高覆盖率把私有实现细节提为 `pub`
- 删改既有测试来让 `cargo test` 变绿——若旧测试与新行为冲突，
  说明是行为变更，走设计文档的「行为变更」流程
