# 测试验证

## 角色

自动生成并执行用例，覆盖功能、边界与回归。
**不为了覆盖率牺牲设计**——这是本项目的明确取舍（`../../rules/09-testing-standard.md` §3）。

- 前置：实施完成且 G4 通过
- 规范：`../../rules/09-testing-standard.md`
- 位置与挂载：`../../../docs/TESTS.md`
- 门禁：`../../rules/07-quality-gates.md` G5

## 四步 SOP

### Step 1 从需求与设计抽用例

- 每条 `R-n` → 至少 1 个用例
- 设计文档「异常与边界」章节 → 逐条对应用例**或**人工项
- 测试注释里标关联：`// R-3: 空库搜索返回空列表`

### Step 2 边界九项逐条定归属

| # | 边界项 | 归属（已测 / 要人工 / 不适用） |
|---|---|---|
| 1 | 空输入 | |
| 2 | 超大输入 | |
| 3 | 非法路径 | |
| 4 | 并发写 | |
| 5 | 外部程序改文件 | |
| 6 | 崩溃后半截文件 | |
| 7 | 多库切换 | |
| 8 | 隐藏与忽略文件 | |
| 9 | 非 UTF-8 | |

判据见 `../requirement-clarify/references/boundary-checklist.md`。
**不适用必须注明理由**，留空视为未做。

### Step 3 执行与回归

```bash
cargo test                      # 全绿
cargo test <关键字>             # 定向跑
```

- 若本次修改了既有行为：检查受影响的旧测试，**并**在设计文档「行为变更」处注明
- 挂载新测试文件：在被测文件末尾加 `#[cfg(test)] #[path = "../../tests/<层>/<模块>.rs"] mod tests;`

### Step 4 处理「测不了」的三原则

1. **写真实用户目录 / 发真实 HTTP** → 抽出纯规则函数测（原样搬移 3~15 行，
   行为不变），函数本身留人工验收
2. **状态迁移在 `cx.listener` 闭包里** → 仅当出过 bug 才为可测性重构
3. **渲染 / 手感 / 着色** → 不硬凑测试，登记到 `../../../docs/ACCEPTANCE.md`

## 强约束

| 编号 | 约束 |
|---|---|
| C-1 | 涉及文件系统的测试必须 `tempfile`，**绝不**污染真实用户目录 |
| C-2 | 不为覆盖率把私有实现提为 `pub` |
| C-3 | 抽函数只做原样搬移，**不为测试改设计** |
| C-4 | 行为变更必须在设计文档注明并检查受影响的旧测试 |
| C-5 | 断言要具体，禁止 `assert!(result.is_ok())` 这类空断言 |
| C-6 | **不删改既有测试来让 `cargo test` 变绿** |
