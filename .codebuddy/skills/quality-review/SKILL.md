# 质量保障

## 角色

交付前的最后一道关：自审 → 静态检查 → 缺陷分级 → 验收交付 → 索引回写。

- 前置：G5 通过
- 门禁：`../../rules/07-quality-gates.md` G6
- 验收规范：`../../rules/10-acceptance.md`

## 五步 SOP

### Step 1 代码自审清单

对照 `../../rules/03-rust-code-style.md` 逐条过：

- [ ] `core/` 无 `unwrap()` / `expect()`（测试代码除外）
- [ ] `core/` 无 gpui 组件类型、无布局样式代码
- [ ] 错误类型分层正确（`core/` = `thiserror` 可匹配；`ui/` = `anyhow` + `context`）
- [ ] 公共 API 有 `///`；注释解释「为什么」而非复述代码
- [ ] `render()` 内无 IO、无重计算
- [ ] 元素 id 用稳定值（文件路径），不用会变化的值
- [ ] 无吞掉的错误（`let _ = ...` 而无注释说明）

### Step 2 静态检查

```bash
cargo clippy --all-targets       # 无 warning
cargo fmt --check                # 无 diff
```

确需 `#[allow(...)]` 的**必须写明原因**——不加说明的 allow 等同于隐藏问题。

### Step 3 缺陷分级

| 级别 | 定义 | 处理 |
|---|---|---|
| **Blocker** | 丢数据、崩溃、编译不过 | **当次必修，不得交付** |
| **Major** | 功能不符需求、明显性能问题 | 记为新任务，下轮修 |
| **Minor** | 体验瑕疵、命名、文档漂移 | 记入 `docs/INDEX.md` §10 已知缺口 |
| **Won't fix** | 明确不做 | 写进设计文档「非目标」 |

### Step 4 验收交付

把只能人眼验的项追加到 `../../../docs/ACCEPTANCE.md`，四列格式：
`# / 验收项 / 怎么验（具体操作）/ 结论`。

- **必须明确告诉用户「这些需要你亲自看」**
- **AI 不得替用户打勾**，未验的保持 ⬜
- 设计文档里的「人工验收清单」章节只放索引，正文进 `ACCEPTANCE.md`

### Step 5 回写索引

更新 `../../../docs/INDEX.md`：

- 新增文档登记一行（状态 + 对应模块）
- 状态标记用图例：✅ 已实现 / ⚠️ 有偏差 / ❌ 不做 / 📦 归档候选
- 新发现的缺口登记进 §10「已知缺口」

> 不回写索引 = 文档漂移。§10 已经有两处文档与代码不一致的历史教训。

## 强约束

| 编号 | 约束 |
|---|---|
| C-1 | 有 Blocker 遗留**不得交付** |
| C-2 | **不替用户在 `ACCEPTANCE.md` 打勾** |
| C-3 | 人工验收项不散落到各设计文档 |
| C-4 | `docs/INDEX.md` 必须回写 |
| C-5 | 不因为"改动很小"跳过自审——小改动是返工的主要来源 |
